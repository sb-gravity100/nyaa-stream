## v0.6.0 implementation lineup (2026-10-29)

This is the consolidated implementation entry point. The feature sections
below remain the detailed specifications. Subtitle styling/smoothing,
context menus, custom magnets, artwork, screenshot/capture thumbnails,
seekbar previews, quiet update checks and the branded NSIS choices page are
implemented on `release/0.6.0`. Manual acceptance remains open for magnets,
live thumbnail capture and partial-file previews. Windows install/update
lifecycle and Fribb mapping-data licensing also remain unresolved; do not tag
v0.6.0 until the readiness checklist is complete. Defaults below are proposed
choices, not previously confirmed SB preferences.

The implementation is integrated, but acceptance is incomplete: disjoint
verified torrent ranges are not storyboarded; arm-server cannot return direct
TMDB or TVDB mappings from an AniList ID; and Fribb's mapping data has no stated
license. The Win10Lite NSIS→NSIS, MSI→MSI and MSI→NSIS upgrade matrix now passes
17/17 checks per route, including launch with app-local `VCRUNTIME140.dll`,
database/marker retention and uninstall. See
[`docs/acceptance/v0.6.0/`](../acceptance/v0.6.0/). The old v0.5.8 baseline used
a runtime test shim so it could launch on the clean VM. The in-app signed
updater lifecycle, clean-machine WebView2 bootstrap, UAC and interactive
installer choices remain unverified. A local signed NSIS artifact has been
generated. The NSIS template
provides a branded install-choice page; its progress and completion remain
NSIS pages.

### Data preservation (required by SB, 2026-10-29)

Preserve permanent release data, source attachments and playback/resume state.
This applies to schema migrations, ML removal, installer upgrades, in-app
updates and app restarts. Retain release records/file lists and custom source
links, watch progress, selected source/file identity, cached resume buffers
and Continue watching. Save active playback position before controlled exit.
Do not clear or rebuild user databases as a migration shortcut. Verify an
existing-profile upgrade and interrupted/failed update retain the same data
and can resume the same source at the saved position.

### ML removal (requested by SB, 2026-10-29)

Remove the cancelled learned-matcher plan, Python training/scoring scripts,
ML-only Rust examples, debugger prediction types/UI and Python process calls,
and static stem-mapper training/holdout invoked during dataset generation.
Preserve rule-based matching, title/stem parsing helpers and old-dataset
schema/import compatibility. Verify frontend build, Rust workspace/examples,
dataset build/import tests and matching diagnostics without ML artifacts.

### Completed subtitle work carried into v0.6.0

SB consolidated all unpublished v0.5.9/v0.5.10 work into this milestone.
- Independent ASS dialogue overrides: font/weight, size, text color,
  outline/background/shadow and bottom margin, shared by mpv, HLS and export.
- Embedded playback uses `blend-subtitles=yes` and `scale=ewa_lanczos`,
  retaining scaler blur 1.5, Mitchell downscaling and subtitle blur 1.0.
- Plain-text mpv subtitles/export use light hinting; styled ASS resets to
  no hinting. HLS uses bounded 1.5x device-pixel supersampling up to the
  2160px threshold, preserving native resolution on larger outputs.
- Existing automated/build checks remain valid; visual playback comparison
  remains open. Native mpv supersampling stays in v0.7.0.

### 1. Context menus
- Targets: text inputs, selected text, anime cards/search results, Continue
  watching, episode rows, source rows and the player. Actions remain those in
  the existing Context menus table; attached custom sources also expose
  edit/remove and hide nyaa-only actions when no nyaa page exists.
- Disabled actions reflect available data; disabled copy/play actions cannot
  execute. Escape, outside click, scroll, blur and navigation close the menu.
  Arrow keys and Enter work; development Shift+right-click keeps Inspect.
- Verify text selection/clipboard, window edges, route changes and player
  shortcuts without replacing the existing speed reset behavior.

### 2. Custom magnets
- Accept `magnet:?` with hex/base32 btih and bare 40-hex hashes. Show decoded
  name, parsed episode hint and tracker count; invalid magnets stay inline
  and never enter anime search. Enforce bounded input and supported fields.
- Direct playback uses the existing player/file menu. Attachment supports
  anime + episode, whole pack or range, detected kind with override, and
  persisted file lists. Use one authoritative schema including kind, season,
  optional episode range and timestamps; migrate the permanent store safely.
- Explicit attachment bypasses title matching, but episode playback still
  uses the pack's season/file mapping and skips extras. Unknown numbering
  stays on a Batch row. Edits/removal must update every affected episode row.
- Verify hash formats/decoding/rejection, metadata-only attachment, sparse and
  multi-season packs, extras, persistence after restart and deletion.

### 3. Artwork and missing thumbnails
- Backdrops: TMDB textless art -> fanart.tv -> Kitsu -> AniList ->
  poster, skipping unavailable providers. Logos fall back to the normal text
  title. Episode art: Kitsu/AniList -> TMDB still -> manual torrent capture.
  Do not fetch or cache images embedded in Nyaa release descriptions. Keep
  episode frames out of backdrop slots.
- Persist per-anime Nyaa release results in localStorage. Reopening an anime
  shows the saved results without another full search; a Refresh button on
  the anime page explicitly fetches and replaces them. Keep the last
  successful results visible if refresh fails.
- Credentials are user-supplied where required, absent providers are skipped,
  and secrets are never logged. Revalidate provider API/attribution/cache
  requirements before implementation; historical provider notes are not a
  substitute for that check. Cache ID maps weekly; implement the documented
  provider cache limits and split-cour episode mapping.
- Build thumbnails only fills visible episodes without art. Rank all seeded
  sources by smallest bytes per episode within the >=3-seeder tier, then the
  >=1-seeder fallback tier; do not give a group a size-order override. Skip
  zero-seeder rows, try at most three candidates, wait no longer than 8s for a
  connected peer, and cap each midpoint capture at 25s. Reuse a batch across
  its files and pause captures during playback.
- Show missing count, completed/total, current-row spinner, Cancel, skipped
  no-seed sources and failures distinctly. Cancel stops after the current
  capture; do not discard thumbnails already completed.
- Verify missing IDs/keys, offline/cached fallback, bad image URLs, cancellation,
  failed swarms, cached results and batch episode attribution.

### 4. Seekbar previews
- Generate frames only from verified local pieces; never trigger torrent
  downloads or player seeks for hover. Missing buckets display time alone.
- Background work pauses while buffering, revisits newly verified ranges,
  stops with playback and follows the existing resume-buffer retention rule.
- Test partially downloaded files, arbitrary seek positions, no keyframe yet,
  player close/resume, and both mpv and HLS hover UI.
- Continuous seekbar dragging and batch next-episode/preload changes stay in
  v0.7.0. A thumbnail preview does not pull those features into v0.6.0.

### 5. Background and in-app updates
- Selected schedule: first quiet check 30s after app readiness; then every
  6 hours while running. A focus/resume event checks only when that interval
  has elapsed. One check may run at a time; offline/server failures back off
  from 15 minutes up to 6 hours. Manual Settings checks remain immediate.
- State model: idle/checking -> available -> downloading -> verifying ->
  ready to restart -> applying at shutdown -> relaunched; report recoverable
  errors with retry. Unknown byte counts/stage durations are indeterminate.
- Header: right-aligned Update button alongside existing actions, visible
  only when an eligible newer published build is available. Clicking opens
  release notes, version and Download update. It does not download merely
  because a background check finds an update.
- Progress stays inside the app. After preparation, offer Restart now or
  Later; Later keeps a restart-ready header action and must not restart
  during playback. Save resume state before an explicit restart.
- Keep signature verification and What's new/version markers. Failed checks
  do not clear a known pending update; failed preparation must not damage
  the current install. Cancel is offered only where the implementation can
  actually stop safely. Never claim installation is complete before the
  new version has launched successfully.
- Windows apply uses the updater plugin's verified payload handoff to the
  native installer. `windows.installMode = passive` runs unattended with a
  progress window; NSIS receives `/P /UPDATE`, and `restartAfterInstall`
  defaults to true. Keep passive mode for elevation and existing-install
  compatibility; Tauri documents quiet mode as unable to request elevation.
  The isolated UAC, migration and relaunch checks remain required.
- Acceptance: quiet checks/no update, availability across routes, manual
  retry, unknown download size, invalid signature, interrupted download,
  preparation failure, playback deferral and verified version after restart.

## Build thumbnails button (planned, v0.6.0 - minor: new feature)

The media page shows Kitsu / AniList / TMDB art or frames already on disk
(`useLocalThumbnails` → `cached_torrent_thumbnail`); an episode without art is
a bare number tile. Nyaa release-description images are not fetched. The
Episodes section button runs the existing scratch-torrent FFmpeg capture.

- **Button:** in the Episodes section header, "Build thumbnails (N)", shown
  only when N > 0 visible episode rows have no thumbnail from any source.
  While running: "Building 3/12 · Cancel"; at the end, "N failed" if any.
- **Which release:** rank every row source with >= 3 seeders by size per
  episode, smallest first; if no source meets that threshold, rank sources
  with >= 1 seeder the same way. Do not prefer a group or standalone episode
  over a smaller source. For a batch, normalize its listed size by the
  matching episode count. Never use a zero-seeder source; if none has a
  seeder, count the row as "no seeded source" rather than a failure. Try no
  more than three candidates. Since nyaa's seed count is only a snapshot,
  abandon a source if no peer connects within 8s.
- **Fetch:** use FFmpeg's direct seekable sbtl reader to seek to the estimated
  episode midpoint and stop after its first decoded frame; do not play from
  the beginning or download the whole torrent. Limit each frame attempt to
  25s, then try the next candidate. Record file bytes fetched, total file
  size, peer count and midpoint so live acceptance can confirm that capture
  stays sparse and quick. If duration is unknown, retain the 8s fallback.
- **Batches:** add one torrent for the pack, match requested episode files,
  capture each from that torrent, then remove it.
- **Queue:** run up to ten frame extractions concurrently across torrent
  batches; episodes from the same magnet share a batch. A worker claims the
  next batch as soon as one finishes. Pause during playback. Cancel lets
  active frames finish and stops queued frames; completed thumbnails stay
  cached.
- **Tiles:** a row being captured shows a spinner; the resulting frame updates
  through `subscribeFrameSaved`, the same notification used for player frames.

Today every wide backdrop (media page, home hero, Continue watching) is
`kitsu.background` (Kitsu `coverImage.original`) → AniList `bannerImage`
(~1900x400, a thin strip) → the poster. Kitsu covers are inconsistent in size
and quality and often missing. Researched 2026-09-29:

| Source | Wide art | Key / terms | ID needed |
|---|---|---|---|
| **TMDB** | backdrops up to 3840x2160 (`original`), textless ones tagged `iso_639_1 = null`; also transparent title **logos** | free for non-commercial use with attribution (TMDB logo + "This product uses the TMDB API but is not endorsed or certified by TMDB" in About) | TMDB tv/movie id |

| **Simkl** | fanart `_medium` 1920x1080 WebP, `_d` original | **Skip**: current official API terms forbid use alongside a competing anime/TV/movie tracker unless the app provides Simkl login and sync | Simkl id |

  TV and movie matches, do not guess; leave TMDB art unavailable. The upstream

  The upstream repository currently does not state a dataset license; keep the

- **Chain:** TMDB textless backdrop (highest vote, >= 1920 wide) → fanart.tv

- **TMDB key: user-supplied, never bundled.** The TMDB key was requested for

  is not shipped in published builds. So: a "TMDB API Read Access Token"

  links to TMDB's API page to get one. The fanart.tv project key and optional
  personal key are user-supplied; neither is bundled.
- **Attribution (TMDB terms):** Settings → About shows TMDB's official logo

  app's own branding, with "This product uses the TMDB API but is not endorsed

## Seek-bar thumbnail preview (planned, v0.6.0 - minor: new feature)

Hovering the player's seek bar shows only a time tooltip today
(`handleSeekHover`, `src/PlayerView.tsx`). Add a small frame preview above
it, like YouTube/Stremio.

- **Storyboard, not live seeks:** a background job in `torrent-engine` (the
  in-process FFmpeg in `media.rs`) decodes **keyframes only**
  (`skip_frame = nokey`) of the playing file and writes one 240x135 JPEG per
  ~5s bucket (the nearest keyframe) to
  `<cache_dir>/nyaa-stream/storyboard/<info_hash>/<file_idx>/`. Keyframe-only
  decode is cheap; a 24-min episode is ~290 frames of a few KB.
- **Downloaded data only:** the job snapshots only the contiguous verified
  prefix and never waits on or prioritizes a missing piece. It revisits the
  prefix as it grows; disjoint verified ranges stay unavailable until gaps
  verify, because FFmpeg must never cross an unverified hole. The preview
  must never cause downloading or compete with playback. With v0.3.2's
  in-order download the storyboard fills from the playhead forward.
- **Paced:** runs at low priority, pauses while playback is buffering, and
  stops with the player.
- **Hover:** the frontend asks for the bucket under the pointer
  (`storyboard_frame(torrent, file, seconds)` → `thumb://` URL or none),
  debounced ~80ms and cached. No frame yet (not downloaded) → time tooltip
  only, as today. Crop letterboxed sources to fill the preview.
- **Cleanup:** the storyboard folder is deleted with the torrent in
  `stop_playback`, and kept alongside a v0.4.0 resume buffer if the episode
  is in Continue watching.
- Not a second libmpv instance: live seeks per hover would decode full
  frames and request undownloaded pieces.

## Custom magnet in the search bar (planned, v0.6.0 - minor feature; was v0.4.5, held out of v0.5.0 on 2026-10-13)

**Request** (2026-10-13): paste a magnet URL into the search bar. Decided
(user): both play it directly **and** let it be attached to an episode.

**Detection.** `src/App.tsx` search input (`placeholder="Search anime"`): a
trimmed value starting `magnet:?` with an `xt=urn:btih:<40 hex | 32 base32>`
is a magnet, never sent to nyaa search or AniList. A bare 40-hex info hash is
accepted too (turned into a magnet). Anything else searches as before.
Invalid magnets (no btih) show an inline "not a valid magnet" hint.

**Play directly.** The bar shows one row "Play this magnet" with the `dn=`
name (or the info hash), the parsed `EpisodeLabel` of that name, and the
trackers count. Enter or click calls `play_magnet` (`src/playback.ts`) with
`title` = `dn`, `episode` = the label's episode if any; the player's file
menu picks the file (its `pickFile` already handles packs), so a magnet
without episode info still plays. A shared `parse_magnet` helper lives in
Rust (`src-tauri/src/magnet.rs`, command `parse_magnet(text) ->
ParsedMagnet{info_hash, name, trackers, label}`) so the frontend does not
re-implement base32/percent decoding; unit tests cover hex/base32 hashes,
`dn` decoding, repeated `tr`, and rejects.

**Attach to an episode.** While it plays (and from the "Play this magnet"
row's menu) an "Attach to episode..." action opens a picker: search the
anime (existing search), choose the media and episode. The attachment is a
row in the permanent store, `custom_sources(info_hash, magnet, name,
anilist_id, season, episode, added_at)`, not a nyaa release; the episode's
source list merges `custom_sources` for that media/episode (marked "custom",
removable from its row's menu). Attached sources bypass title matching (user
chose the episode); a pack attaches to the media and is offered per episode
via the file-list check like other packs.

**Tasks** (one commit each): M1 `parse_magnet` + tests; M2 search-bar
detection and the "Play this magnet" row; M3 `custom_sources` table + store
API; M4 attach picker and merge into `groupedSources`; M5 docs, CHANGELOG,
FILE_INDEX, version.

**Batches and packs.** A pasted magnet is often a batch, and nothing in the
magnet says so (only `dn`). Rules:
- *Kind detection:* the `dn` label (`EpisodeLabel::kind`: batch / range /
  episode / unknown) is only a hint. The truth is the file list: after the
  torrent's metadata arrives (the engine already fetches it on play), count
  video files (skip `EXTRA_FILE` names), and treat 2+ as a pack. The
  attach picker shows the detected kind and lets the user override it
  ("single episode" / "batch"). The metadata fetch for an attach that is not
  playing goes through the same sbtl metadata-only path as `fetch_details`
  (no piece downloads); the file list is stored on the `custom_sources` row.
- *Play directly:* a pack opens in the player with the file menu listing all
  videos; with a parsed episode in the query context (attached from an
  episode row) `pickFile` chooses that episode's file, otherwise the first
  episode file (lowest season/episode, extras last), never an OVA/NCOP.
- *Attach, single episode:* `custom_sources` row with `kind = episode`,
  explicit season + episode.
- *Attach, batch:* the picker offers "whole pack for <media>" (default) or
  a range. The row stores `kind = pack`, `season` (the entry's season by
  default, from `get_entry_season`), optional `episode_from/episode_to`,
  and the file list. `groupedSources` offers it on every covered episode
  row with `explicit = true` (the user chose it, so no file-list
  confirmation or season guessing is needed), and the player picks that
  episode's file by season and number with the existing `pickFile` logic
  (`TorrentDetails.seasons` per file, parent-folder season fallback). Files
  of other seasons in a multi-season pack stay unselected unless the
  entry's season matches.
- *Pack with unknown numbering* (no usable numbers in file names): the
  attach picker warns, and the pack stays on a "Batch" row for the media
  instead of per-episode rows.
- *Edits:* an attached pack can be re-attached to another media/season, and
  removing it removes it from all its episode rows.

**Rules.** No network lookup for a pasted magnet beyond what playback does;
a magnet from the clipboard is untrusted input: only `btih`, `dn`, `tr` are
read and everything is length-capped.
